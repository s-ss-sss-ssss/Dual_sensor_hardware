# TMAG 实验异常分析（2026-10-10）

依据：当前仓库源码、`log-26-10-10.md`、本地英文手册 `TI_TMAG3001_Datasheet_EN.pdf`（SLYS053C，May 2025）。补充参考 TI 的 TCA9548A 英文手册和 I²C 上拉电阻计算应用报告。仅做静态分析，未接入实物、未烧录或修改固件。设备上实际二进制是否与当前源码一致尚未验证。

## 1. 核心判断

实验并没有收到 XYZ=(0,0,0) 的 TMAG 数据，而是根本没有 TMAG TLV，且累计 `tmag_frames=0`、`skipped=0`。应首先定位“为何没有器件进入采集路径”，然后才讨论零磁场值。

当前默认 `SENSOR_OUTPUT_TMAG=1`，AK 与 ICM 输出均为 0。因此 AK/ICM 没有记录符合默认配置，不能据此推断三个传感器系统同时故障。ICM 初始化仍会执行，但其输出关闭。

最符合日志的候选链路是：I²C/硬件映射或配置回读异常 -> TMAG 初始化失败 -> 所有 `inited=0` -> 主循环跳过 TMAG -> 持续发送仅含 PHASE 的 ROUND。此为基于源码的推断，必须用启动日志确认。

## 2. 初始化失败后会长期没有数据

代码位置：`Core/Src/main.c:345`，`Core/Src/sensor_tmag3001.c:475`、`:597`，`Core/Src/tmag3001.c:106`。

- `main()` 最多尝试 5 次初始化，即使没有一颗成功，也继续进入主循环。
- `TMAG3001_Init()` 要求厂家 ID、多个配置寄存器写后回读、连续模式写后回读和结果就绪检查全部成功。
- 任一步失败，实例不置 `inited=1`。主循环只访问已初始化实例，没有后台重探测；接线或供电后来恢复，也不会自动重新加入。
- 未初始化实例既不产生 TMAG TLV，也不增加运行期 `skipped`。因此“TMAG=0、skipped=0”优先指向未进入读取路径。
- 如果器件初始化成功，但不断读到 `Result_Status=0`，代码会增加 `skipped`；如果访问失败，会增加 `errors` 并尝试追加 ERR。当前观测并不优先支持这两种持续故障。

首先应读取 USART1 启动日志，找 `TCA not responding`、`TCA select FAIL`、`TMAG CHn: n/3 OK` 和最终初始化数量。二进制模式的 `printf()` 仅走 USART1，USB CDC 看不到这些文本。接口为 PA9/TX、PA10/RX，115200 8N1，使用与板卡兼容的 TTL 电平并共地。

初始化诊断目前只报告每通道成功数量，不能区分 ID 失败、哪次写入失败或 DRDY 超时。建议补充：通道、地址、步骤、寄存器、写入值、回读值、HAL 返回值和即时 `HAL_I2C_GetError()`。错误码要在总线恢复前保存，恢复/重初始化可能清除原始错误。

## 3. 实物拓扑与固件配置存在需要核实的差异

代码位置：`Core/Inc/sensor_tmag3001.h:7`，`Core/Src/sensor_tmag3001.c:496`。

仓库说明写的是 4 颗、每通道一颗；实际代码配置是 12 颗：TCA 的 CH1、CH2、CH3、CH4，各扫描 0x34、0x35、0x36。掩码为 0x02、0x04、0x08、0x10，完全不扫描 CH0，也不扫描 0x37。

必须明确实际 PCB/线缆的 TCA 通道编号（从 0 还是从 1 命名），以及每颗 ADDR 的连接。英文手册 §6.3.5、Table 6-4（p.20）对应：GND=0x34、VCC=0x35、SDA=0x36、SCL=0x37。

如果实物每通道仅一颗 0x34，期望 12 颗会导致反复初始化，但只要通道正确，已有的 0x34 仍应被读取；“数量不一致”本身不足以解释全部缺失。若全部接在未扫描通道或地址上，则可直接解释全无记录。

同一个 TCA 分支上多颗同地址不能独立访问。扫描时 ACK 和正确厂家 ID 也不能证明没有地址冲突，因为多个同型号器件可以同时应答。不同分支允许地址重复，前提是只选中一个分支。

## 4. 通信协议与寄存器核对

英文手册 §6.5.1.2.3、§7.1.1-7.1.4、§7.1.25；主要对应 p.27、41-44、57。

| 项目 | 当前实现 | 判断 |
| --- | --- | --- |
| 地址格式 | 7 位地址传给 HAL 前左移一位 | 正确；0x34 对应线上写地址 0x68、读地址 0x69 |
| 标准读取 | `HAL_I2C_Mem_Read`：写寄存器指针、重复 START、读取 | 与 I2C_RD=0 的标准读模式相符 |
| Device_Config_1 | 0x00 | CRC 关闭，平均 1x，标准寄存器读，正确 |
| Device_Config_2 | 先 0x00，最后 0x02 | 待机配置后进入连续模式，正确 |
| Sensor_Config_1 | 0x70 | MAG_CH_EN=7，即 XYZ 使能，正确 |
| Sensor_Config_2 | 0x00 | 默认量程，无角度计算，正确 |
| 原始数据 | 从 0x12 连读 7 字节 | XYZ 大端有符号值，再读取 0x18 状态，正确 |
| 厂家 ID | 0x0E/0x0F 组合为 0x5449 | 正确，但不是型号独占的身份证明；还应读取 Device_ID |
| 就绪判断 | 0x18 bit0 | Result_Status，定义正确 |
| `STATUS_OVF=0x02` | 被打包为 overflow | **明确错误：bit1 是 Diag_Status，表示内部诊断失败** |

overflow 的误命名不直接造成 TMAG 记录消失，但会误导后续故障诊断。应读取 0x1C 的 OTP_CRC_ER/INT_ER，区分诊断错误。当前代码也没有处理运行中的 POR（0x18 bit4）和配置丢失。

0x09 写 0 不应简单理解为“增益乘零”：英文手册 §6.5.2.3 明确说 Gain_Config=0 禁用该增益校正，且当前 Angle_EN=0。因此它不是当前全零的充分原因。

5 ms 的就绪等待在当前 1x/XYZ 配置下通常足够。手册给出连续测量启动最大 70 µs，1x 三轴约 10.5 ksps；不能把超时过短列为首要原因。头文件中“1x 约 100 µs”是粗略描述，而单轴转换时间表典型值为 50 µs，需区分单轴与三轴。

初始化开头两次 `write_reg()` 忽略返回值，是诊断缺陷。虽然后续有回读检查，但第一处故障被掩盖。`read_mfg_id_retry()` 在总线读成功但 ID 不符时也可能返回 HAL_OK；Init/Probe 的额外 ID 比较可拦截它，所以这不是当前直接放行错误器件的证据。

## 5. 读取频率与总线带宽

代码位置：`Core/Src/main.c:381`，`Core/Src/i2c.c:132`，`Core/Src/main.c:524`。

主循环没有固定周期或空轮限频。每轮尝试采集、追加 PHASE，随后阻塞等待 USB 发送结束。无器件被读取时，31 字节空轮能达到日志中的约 8.3 kHz；这不是磁力计采样率。

当前 HSE=25 MHz、PLL M=5/N=48/P=2，因此系统时钟为 120 MHz，APB1/I²C123 内核时钟为 30 MHz，而非 MCU 标称最高 480 MHz。I2C3 TIMINGR=0x007074AF：PRESC=0、SCLH=116、SCLL=175，基本高低周期合计 293/30 MHz≈9.77 µs；考虑同步、滤波、上升下降时间后为约 100 kHz，应以示波器实测为准。

标准读 7 字节的 SCL 数量：地址写 9 + 指针 9 + 地址读 9 + 7 字节数据及 ACK/NACK 63 = **90 个时钟**。100 kHz 下单颗约 0.9 ms，尚未计软件/起停开销。

| 阵列数量 | 数据读取时钟 | 4 次 TCA 选择时钟 | 100 kHz 理想整轮上限 |
| --- | --- | --- | --- |
| 4 颗（每通道 1 颗） | 360 | 72 | 约 231 Hz |
| 12 颗（每通道 3 颗） | 1080 | 72 | 约 87 Hz |

当前每通道还有一次恢复后重新选择，另加 72 个选择时钟/整轮；以及 4×72 个恢复脉冲、各通道的 18/36 个器件恢复脉冲。实际完整阵列频率低于上表，错误重试及 USB 等待进一步降低速度。

因此正常的完整阵列读取不可能达到 8.3 kHz。5 ms 单次 HAL 超时对正常 0.9 ms 事务也有余量；故障时重试会拖慢循环，不会提高有效频率。

传感器内部连续转换约 10.5 ksps，不等于主机逐次读回率。慢速轮询会漏掉中间转换，快速读取可能重复最新结果。建议保留 Set_Count（0x18 bits7:5）以辅助观察更新，注意它只有 3 位，回绕后不能单独精确统计丢样。各器件自由连续运行也不保证阵列同时采样，ROUND 的 read_done_offset_us 是读取完成时间，而非磁场转换时间。

TMAG3001 本身支持到 1 MHz，不能说手册要求只能用 100 kHz；但 TCA9548A 最大 400 kHz，使本拓扑上限为 400 kHz。即使升至 400 kHz，12 颗标准读取的理想整轮上限也只有约 347 Hz，且必须先验证波形与上拉。

## 6. 恢复波形和推挽驱动：明确的高优先级代码风险

代码位置：`Core/Src/sensor_tmag3001.c:76`、`:110`、`:132`、`:177`、`:369`；`Core/Src/i2c_recovery.c:102`。

正常 I²C 配置是开漏，但多处恢复将 SDA/SCL 改为 `OUTPUT_PP` 或清除 OTYPER 位，并主动输出高电平。如果传感器仍在拉低 SDA、或 SCL 被拉低，MCU 高侧驱动就会与器件争用。此时“强制拉高”不等于正确释放总线，可能造成低电平抬升、过流、错误边沿，甚至损伤。

二进制正常采集每通道会无条件执行 72 个脉冲，再选一次 TCA；每个非 GND 地址还执行 18/36 个脉冲。标准 HAL 正常读已经用 NACK/STOP 结束，不应依赖每次成功事务前都强制清总线。

`TMAG_PULSE_HALF_US=1` 给出的目标波形约 500 kHz，而注释声称约 100 kHz。实际指令开销会降低频率，需测量；但没有保证 TCA 的 400 kHz 上限和 Fast-mode 最小低周期 1.3 µs。此处属于独立于正常 100 kHz 配置的时序风险。

建议只在确认总线卡住或通信失败时恢复，使用开漏方式释放高电平，检测实际 SDA/SCL 电平，遵守 clock stretching 和起停时序。先用单颗器件比较“标准事务、关闭无条件脉冲”和当前恢复策略，不能仅通过增加脉冲数量认定已经修复。

重要边界：无条件脉冲主要位于运行期读路径；若启动后根本没有 inited 器件，这些脉冲不会执行，不能直接把它们当作本次启动失败的已确认原因。初始化失败后的硬件复位则会执行。

## 7. RESET、供电、电平、上拉和布线

`tmag_hardware_reset()` 注释称 PC8 会复位 TCA 和所有 TMAG，但 TMAG3001 的 6 引脚为 VCC/GND/ADDR/INT/SDA/SCL，没有独立 RESET。若 PC8 仅接 TCA RESET，它只复位 mux 并取消全部通道，无法恢复 TMAG 的寄存器、工作模式或地址。若板上另外接电源开关，才可能复位传感器；必须对照原理图和实测确认。当前 doc 未提供电路原理图，不能确认网络连接。

TMAG 英文手册 §5.3/5.5/8.4：

- 供电工作范围 1.65-3.6 V；在传感器焊盘测量，不只在 MCU 板接口测量。检查启动和采集时瞬态跌落、共地与连接器接触。
- 3.3 V 供电时 VIH 最低约 2.145 V、VIL 最高约 1.155 V；SDA 在 2 mA 下 VOL 最大 0.4 V。逻辑分析仪能解码不代表电平裕量足够。
- 推荐 SDA/INT 输出电压上限 3.6 V，不能因为 TCA 允许 5 V 就直接把 TMAG 支路上拉到 5 V。
- 需要器件旁去耦，手册要求至少 0.01 µF 陶瓷电容；实际可根据布局/电源设计配置 0.1 µF 和板级储能。
- ADDR 应按实际供电连接 GND/VCC/SDA/SCL。“A2=3V3”的代码名不能替代电路判断；A2 同时容易与型号后缀 A2（量程版本）混淆。

TCA 是双向开关，并非隔离所有电容的有源缓冲器。主干和各下游分支应有按各自电平设计的外部上拉；跨电压使用需按 TCA 的 Vpass 条件设计。STM32 的内部 GPIO_PULLUP 不能代替对整个阵列上拉的计算。选通支路上的主干/支路上拉可能共同形成低电平负载，计算应包含所有参与的电阻。

I²C 的“阻抗匹配”重点是上拉电阻、总电容、开关电阻、边沿及灌电流，不应直接套用射频 50 Ω 终端。

依据 TI SLVA689：`tr≈0.8473×Rp×Cb`，`Rp,max=tr,max/(0.8473×Cb)`，`Rp,min=(Vpullup−VOL,max)/IOL`。例：Cb=200 pF，100 kHz 按 1 µs 上升时间预算，Rp,max≈5.9 kΩ；400 kHz 按 300 ns，Rp,max≈1.77 kΩ。若实际测得 4.7 kΩ、200 pF，tr≈0.80 µs，无法满足 400 kHz 的 300 ns 要求。以 TMAG 2 mA/VOL=0.4 V 保证条件作保守计算，3.3 V 下 Rp,min≈1.45 kΩ，400 kHz 的余量很小；还要检查 MCU/TCA 条件与并联上拉。

这些是条件化算例，不是本板测量值，不能据此直接规定改成某个电阻。应在 MCU 端和选中支路最远器件端测量高低电平、30%-70% 上升时间、振铃、ACK 和时钟周期。长线、星形支路、连接器和探头都增加电容；必要时缩短线缆或使用符合本协议的缓冲方案。串联阻尼需根据实际波形选择，不能盲加大串阻。

## 8. STATS、USB 和 PHASE 的解释

运行期 `errors` 在进入主循环后才从 0 开始，**当前代码没有把初始化失败计入这个 STATS 字段**。所以不能把 3778/5176 直接解读为 TMAG 初始化错误数。

如果确认运行的正是当前源码，且 TMAG 初始化数量为 0，则这一配置下 errors 增长主要需要查构帧/USB 发送失败，而非被跳过的 TMAG。USB 失败会设置 pending_usb_failures，后续成功发送时应追加 source=4 的 ERR；“某个短窗口无 ERR”可以表示错误发生在窗口之前，不能据此判定整个运行期间从未发送 ERR。如果复现实验中 errors 持续增长、成功帧却始终无 ERR，应核对实际烧录版本与抓包解析。

USB CDC 的 115200 line coding 不是这条 USB 通道的带宽限制；USART1 文本日志才实际使用 115200。USB 的 CRC 正常仅证明应用帧传输/构造通过校验，无法证明 I²C 读过传感器。

PHASE 的全 0xFFFFFFFF 表示 PA0/PA1/PA2 从未获得有效 TIM2 捕获；当前 TMAG 连续模式和读循环不以 PHASE 有效作为前提，所以它不是传感器记录缺失的直接软件门控。独立检查外部信号、共地、电平和输入映射。

无周期约束的 8.3 kHz 空轮会给 ROS 的小队列造成压力。日志短时直接读取没有序号缺口，而 ROS 存在缺口，优先做分段序号对照；同时当前 round_seq 在构帧/发送前递增，设备发送失败也能产生缺口。CRC=0 不能排除整帧丢失。

## 9. 下一轮实验顺序与判据

1. 记录实际固件版本/构建宏；复位前连接 USART1 抓取全程启动日志，明确 TMAG 初始化数量。先不做大规模改驱动。
2. 只连接一颗确定通道、ADDR=GND 的 TMAG。测 VCC/GND/RESET，确认 TCA 0x70 ACK，写并回读通道掩码，再读 0x34。不要只做上游地址扫描。
3. 保存厂家 ID、Device_ID、0x00-0x0C 配置和 0x18/0x1C 状态；关键目标 0x00=00、0x01=02、0x02=70、0x03=00，0x0E/0x0F=49/54。区分地址 ACK 失败与读回值错误。
4. 抓取一次完整波形：TCA 选择完成并 STOP；0x68/W -> 指针 0x12 -> repeated START -> 0x69/R -> 7 字节 -> 最后一字节 NACK -> STOP。测两端电平和边沿，观察有无推挽恢复争用。
5. 在受控诊断配置中关闭成功事务前的无条件脉冲，保留开漏、按故障触发的恢复；单颗先以 50-100 Hz 轮询保存原始 7 字节。移动磁铁时 XYZ 应变化，同时应出现 TMAG TLV、tmag_frames 增长。Result_Status 不完整时保存状态，而不是用零填充磁场。
6. 逐颗、逐分支扩展，核对实际地址与初始化数。若“一颗好、多颗坏”，优先检查地址冲突、供电及并联上拉/电容；若“上游好、下游坏”，检查 TCA 通道/RESET/支路上拉。
7. 完整阵列恢复后再设计采样/发送周期、需要的同步策略、PHASE 和 ROS 队列。先以 10-50 Hz 完整阵列验证，依据实测总线预算提高速率；若需全阵列 kHz 级采样，应重新设计总线并行度/读取方案，单纯调主循环不能实现。

## 10. 优先级汇总

| 优先级 | 候选原因或代码问题 | 与当前日志的关系 | 验证方式 |
| --- | --- | --- | --- |
| P1 | 初始化全失败后永久跳过 | 最吻合 TMAG=0、skipped=0、空轮高频 | USART1 启动日志 + GetCount |
| P1 | 通道/地址、TCA RESET、供电、下游上拉不符 | 可导致初始化全失败 | 单颗拓扑 + ACK/ID + 电压/波形 |
| P1 | 初始化诊断不足、实际烧录版本未知 | 当前无法分清失败步骤 | 版本信息 + 逐寄存器诊断 |
| P2 | 推挽恢复与无条件快速脉冲 | 确定存在的电气/时序风险；未证实为本次启动根因 | 开漏恢复对照 + 示波器 |
| P2 | 无节拍空 ROUND、USB/ROS 压力 | 可解释高空轮频率及部分序号缺口 | 限频实验 + 分段序号 |
| P2 | POR/配置丢失后没有重配置 | 可造成启动后失采 | 0x18/0x1C 与配置回读 |
| P3 | bit1 错当 overflow | 已确认状态定义错误，不解释全部无记录 | 改诊断语义后验证 |
| P3 | PHASE 无输入或映射错误 | 独立异常，没有 TMAG 软件门控 | PA0-PA2 波形/捕获计数 |
